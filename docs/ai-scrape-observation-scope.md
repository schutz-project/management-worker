# AI 분석의 수집 실패·서비스 중단 구분

## 배경

2026-10-26 Blackbox 자체 지표 수집 경로 오류 시험에서 실제 경보→사건→최초 Slack→AI→AI 완료 Slack→복구 Slack 처리는 성공했습니다. 그러나 AI 요약은 Blackbox 서비스가 내려갔다고 표현했습니다. 시험은 컨테이너를 중단하지 않고 자체 지표 수집 경로만 변경했으므로 수집 실패와 서비스 중단을 구분해야 합니다.

## 변경

- `monitoring_target_down` 분석 입력에 관측 범위를 추가합니다. 확인된 사실은 기록 시점의 Prometheus 수집 실패이며 서비스 가용성·컨테이너 실행·원인은 미확인으로 명시합니다.
- 경로·HTTP 상태·인증·TLS·네트워크·타임아웃·응답 형식 오류는 가능한 원인 후보로만 설명하도록 요청합니다. 기능 점검 성공과 자체 지표 수집 실패가 동시에 가능함을 명시합니다.
- 관측 시점과 현재 상태를 구분하고, 별도 근거 없이 복구·시험 성공·알림 성공을 주장하지 않도록 요청합니다.
- 설명은 한국어, 근거 ID는 원문 유지하도록 요청합니다. 출력 JSON 5개 필드와 기존 근거 ID 검증은 유지합니다.
- 프롬프트 버전은 `evidence-scrape-scope-v2`로 저장합니다. 기존 저장 결과를 바꾸거나 실패 작업을 자동 재실행하지 않습니다.

이번 변경은 입력·프롬프트 개선입니다. 의미상 과장을 완전히 차단하는 출력 판별기는 아니며, 실제 모델의 응답 품질은 승인 후 별도 검증해야 합니다. 현재 collector가 scrape lastError·HTTP 응답·컨테이너 상태를 근거에 제공하지 않으므로 원인을 확정할 수 없습니다. 이 데이터를 수집했다고 가장하지 않습니다.

## 검증과 배포 범위

새 테스트 4개는 수집 범위 입력, 다른 규칙의 분리, 기존 근거 ID 검증, 프롬프트 버전 저장을 확인합니다. 기존 AI 제한시간 4개와 경보 통합 18개를 포함해 26개를 외부 호출 없이 검사합니다.

Worker만 변경합니다. Web UI·DB 스키마·서버 환경·네트워크·경보 규칙 변경은 없습니다. 초안 PR으로 준비하며 병합·배포는 별도 승인 후 진행합니다. 과거 이력 활용 PR #7과 jobs.py 변경이 겹치므로 두 PR을 연속 병합하기 전 프롬프트 내용을 통합하고 회귀 시험을 다시 수행해야 합니다.
