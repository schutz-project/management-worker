# 과거 장애·조치 이력을 활용한 AI 분석

## 이번 변경

Management Worker만 변경합니다. 사건 생성 후 AI 작업이 처음 입력을 저장할 때 현재 근거와 과거 사건을 구분해서 스냅샷으로 보존합니다. 별도 벡터 DB·외부 검색·새 DB 테이블을 추가하지 않습니다. Web 화면 변경, AWS·네트워크·Compose 수정, 병합·배포는 이 PR 범위 밖입니다.

`AI_HISTORY_ENABLED=false`가 기본입니다. 검토·승인 후 별도 배포와 명시적인 설정 변경을 해야 실제 과거 기록을 전송합니다. 활성화된 상태에서 처음 스냅샷을 만드는 AI 작업에만 적용됩니다. 기존 스냅샷·완료 작업을 재생성하거나 자동 재분석하지 않습니다.

## 선택 기준

- 현재 사건과 대상·규칙·모의 여부가 모두 동일해야 합니다.
- 현재 사건 탐지 시각 이전에 종료됐고, 종료 시각이 최근 90일 이내여야 합니다.
- 종료 이전에 작성한 조치(kind=action)가 있어야 합니다. 단순 메모만 있는 사건은 제외합니다.
- 최신 종료 순 최대 3건, 건당 조치 3개·각 500자까지 사용합니다.
- 현재 관측 근거가 없으면 과거 이력을 추가하지 않습니다.
- 대상이 다르거나 규칙이 다른 유사 사건의 의미 검색은 후속 범위입니다. 대상 식별자가 바뀌면 과거 기록이 매칭되지 않을 수 있습니다.

## AI 입력과 한계

현재 근거는 기존 evidence ID를 사용하고, 과거 기록은 `history:<incident_id>`와 `kind=historical_context`로 구분합니다. 종료 시각, 과거 사건 ID, 제한된 조치 내용만 전달합니다. 사용자 이름·작업자 ID·과거 원본 로그·과거 AI 추론·자유 형식 종료 사유는 추가로 전달하지 않습니다.

AI 프롬프트는 한국어 결과, 관측 사실과 가설 구분, 과거 조치 효과의 미검증 표시, 부족한 근거 명시를 요청합니다. 과거 기록은 현재 장애의 원인·복구를 증명하지 않으며 자동 명령 실행이나 자동 복구에 사용하지 않습니다. 과거 이력을 인용하는 결과도 현재 근거 ID를 하나 이상 인용해야 통과합니다. 출력 JSON 계약은 유지합니다.

조치 문장은 신뢰할 수 없는 데이터로 전달합니다. 알려진 비밀번호·토큰 표기, Bearer 토큰, URL을 최선 노력으로 가리지만 모든 개인정보·비밀정보를 탐지하는 기능은 아닙니다. 조치 기록 자체에 비밀정보를 입력하지 않아야 하며 활성화 전 외부 AI 제공 범위를 검토해야 합니다. 미인식 민감정보가 포함된 기록은 외부 전송될 수 있습니다.

현재도 AI 외부 요청은 기존 timeout·재시도·출력 검증을 사용합니다. 과거 이력이 없는 것은 분석 실패 사유가 아닙니다. 과거 사건 선택과 저장 중 DB 오류가 발생하면 트랜잭션을 취소하고 기존 Worker 오류 처리 경로를 따릅니다. 실패를 조용히 무시해 이력 포함 여부를 숨기지 않습니다.

## 재현·복구

`incident_jobs.input_evidence`에 입력을 고정해 재시도 시 과거 기록이 바뀌어도 같은 스냅샷을 재사용합니다. 프롬프트 버전은 과거 이력 포함 시 `evidence-history-v1`, 미포함 시 `evidence-v2`입니다. SQL 스키마 변경은 없습니다.

설정 false는 이후 새 스냅샷의 과거 조회만 중단합니다. 이미 고정된 입력에서 과거 기록을 삭제하거나 대기 중 외부 호출을 취소하지 않습니다. 완전한 코드 원상복구는 배포 전 Worker 이미지 태그를 보존한 뒤 이전 이미지로 수행합니다. 기존 입력·사건·조치 이력은 삭제하지 않습니다.

## 검증 및 다음 단계

외부 통신을 모의 처리하고 메모리 SQLite로 범위 필터, 시간 경계, 건수·문장 제한, 알려진 비밀 표기 가림, 기본 비활성화, 재시도 입력 고정, 현재 근거 인용 조건을 검사합니다. 기존 AI 제한시간·Prometheus 통합 회귀 시험도 유지합니다. CI는 Docker 이미지에서 네트워크를 차단한 상태로 실행합니다.

운영 PostgreSQL 쿼리 성능과 실제 AI의 한국어·가설 품질은 아직 검증하지 않았습니다. 서버 엔지니어 작업 종료 후 승인된 별도 시험이 필요합니다. 현재 조회는 기존 target_id 인덱스를 사용하며 대규모 데이터 성능이 확인되지 않았으므로 유사도 검색이나 추가 인덱스는 임의로 도입하지 않습니다.

다음 UI 검토에서는 현재 근거·과거 조치·AI 가설을 분리 표시하고, 과거 사건 링크 및 입력에 포함된 이력 수를 제공하는 방향을 제안합니다. 이번 PR은 입력 구조와 처리 로직만 구현합니다.
